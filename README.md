# Chitchat

A small-talk practice app. This scaffold includes an SSR web frontend, a shared API with authentication, PostgreSQL, and a voice-interface preview.

## Local development

Requires Bun 1.4.2, Node.js 24+ (Portless and development CLIs), and Docker.

```sh
bun install --frozen-lockfile
cp apps/web/.env.example apps/web/.env
cp apps/backend/.env.example apps/backend/.env
cp packages/db/.env.example packages/db/.env
```

Set `BETTER_AUTH_SECRET` in `apps/backend/.env` to a random secret, for example one generated by `openssl rand -base64 48`. Local environment files and a generated secret have already been created in this workspace; the copy steps are for a fresh checkout.

```sh
docker compose up -d --wait
bun run db:deploy
bun run dev
```

| Service | Local URL |
| --- | --- |
| Web | https://chitchat.local |
| API health | https://api.chitchat.local/health |
| Email preview | https://email.chitchat.local |

Portless assigns a free port to each app. Names and scripts live in each app's `portless.json`. These URLs match this machine's existing HTTPS/LAN proxy configuration. Run `bunx portless doctor` to inspect it or `bunx portless list` to see active routes.

On a machine using Portless's default `.localhost` mode, update `VITE_API_URL`, `VITE_SITE_URL`, `WEB_ORIGIN`, and `BETTER_AUTH_URL` to use `.localhost`. Restart development servers after changing environment files. Portless handles local certificates; first-time setup may request OS authorization.

PostgreSQL uses `localhost:55432` and a project-specific Docker volume. Override `CHITCHAT_DB_PORT` for Compose and update both `DATABASE_URL` values if needed. Portless routes HTTP services, not PostgreSQL.

## Workspace

For isolated agent checkouts, see [Agent worktrees](docs/worktrees.md):

```sh
bun install --frozen-lockfile
bun run worktree:setup  # isolated PostgreSQL, migrations, environment, and color URLs
bun run dev
# In another terminal:
bun run worktree:check
bun run worktree:status
# Before removing the worktree, including after merging:
bun run worktree:teardown
```

Setup works in linked worktrees and ordinary checkouts. Each assigned color stays reserved until teardown. Use `--color coral` for a preferred available color, or `worktree:status --output .worktree/status.json` for agent-readable metadata.

```text
apps/web          TanStack Start, React, Router, Query; Cloudflare Workers
apps/backend      Hono on Bun; Better Auth; server-only Gemini token provisioning
packages/contracts Shared Zod API schemas
packages/db       Prisma client, PostgreSQL schema, migrations
packages/email    React Email templates and preview server
packages/worktree Agent worktree provisioning, checks, and cleanup
```

The landing page is server-rendered with title, description, Open Graph metadata, and a canonical URL. `/practice-design` provides continuous voice practice using server-owned personas, places, and settings from Hono. The retired `/practice` URL permanently redirects to `/practice-design`. Each SSR request gets a separate Query cache.

Hono owns authentication and product data. Better Auth is mounted at `/api/auth/*`; `/api/me` requires a session and is never cached. The browser auth client is in `apps/web/src/lib/auth-client.ts`. Auth forms are a follow-up feature.

Auth cookies are currently scoped to the API host. Public SSR does not fetch private account data. When adding private SSR routes, implement a deliberate cookie-forwarding/proxy strategy (or shared parent-domain cookies for web/API subdomains), and forward cookies only to the configured backend. Keep business logic in Hono. Native session storage and Expo auth integration will be added with the mobile client.

## UI sources

1. [ReUI](https://reui.io/components): primary component registry, configured as `@reui`.
2. [ElevenLabs UI](https://ui.elevenlabs.io/docs): audio components, configured as `@elevenlabs`.
3. [shadcn/ui](https://ui.shadcn.com): supporting primitives.

The badge comes from ReUI. The button and card are shadcn primitives installed as dependencies of a ReUI card example. The Bar Visualizer was installed through shadcn from ElevenLabs' official GitHub registry because its hosted registry returned HTTP 429:

```sh
cd apps/web
bunx --bun shadcn add @reui/badge
bunx --bun shadcn add https://raw.githubusercontent.com/elevenlabs/ui/main/apps/www/public/r/bar-visualizer.json
```

The landing-page preview does not request microphone access. Starting a practice conversation requests the microphone and connects to Gemini Live; using ElevenLabs UI does not require ElevenLabs service credentials.

## Independent practice captions

Practice uses two Gemini connections: `gemini-3.1-flash-live-preview` for the
spoken conversation and `gemini-3.5-transcribe-live` for dedicated speech-to-text.
Both use the existing backend key (`GEMINI_API_KEY`, falling back to
`GEMINI_API_KEY_LIVE`). No additional provider or key is required. Hono issues
separate one-use, model-constrained ephemeral tokens; browsers send the same
native-rate PCM microphone chunks directly to each Gemini connection.

Dedicated captions use `VERBATIM` mode with an English language hint. Interim
hypotheses replace earlier partial text, and final segments replace their
preview. No grammar cleanup is applied. Ending practice stops capture and allows
three seconds for final captions before the backend assesses the transcript. Mute ends both audio
streams; unmute resumes them. Leaving practice closes both connections.

If transcription provisioning or streaming fails, conversation continues with
the voice agent's standard captions and a notice. An interrupted caption can
remain partial. Dedicated transcription currently supports sessions up to ten
minutes; if it expires during a longer practice, the same fallback applies.
Custom-place and custom-situation setup conversations retain standard captions.
The second Gemini connection incurs separate transcription usage.

Tests cover token constraints, shared audio, revised captions, mute, cleanup,
and fallback. Recognition accuracy still needs comparison with representative
human speech. See [Gemini Live transcription](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe).

## Deployment

- **Web / Cloudflare Workers:** set production `VITE_API_URL` and `VITE_SITE_URL` before building. Run `bun run deploy` in `apps/web` after authenticating Wrangler. `apps/web/wrangler.jsonc` contains the Worker configuration.
- **API / Railway:** use the repository root as the build context and `apps/backend/railway.json` as the service configuration. The Dockerfile builds the Bun API. Set the backend environment variables from `.env.example`, including the production web origin and API URL, and use Railway's PostgreSQL connection URL. Railway provides `PORT`.
- Apply `bun run db:deploy` against the production database as a release step before routing traffic to schema-dependent changes. Database migrations are not run automatically during application startup.
- Keep production web/API hosts under the same registrable domain for cookie-based web auth. Provisioning, DNS, and production credentials are not included in the scaffold.

## Voice practice

Set `GEMINI_API_KEY` in `apps/backend/.env`, then open `/practice-design`. `GEMINI_API_KEY_LIVE` is used if the general key is missing. Reply suggestions, Guided text, and Guided speech also retry once with a distinct `GEMINI_API_KEY_LIVE` on quota or temporary provider errors; other practice operations retain their primary key. Choose a persona, place, and setting, then start and talk naturally. The app uses **`gemini-3.1-flash-live-preview`** for continuous audio input and spoken output, with automatic speech detection and interruptions. After practice, `gemini-3.6-flash` assesses the finalized transcript and `gemini-3.1-flash-tts-preview` speaks confirmed feedback in the selected partner’s voice.

The Hono backend uses the pinned `@google/genai` SDK to issue a one-use ephemeral token with a 60-second connection window and 15-minute lifetime. The token locks the model, persona instructions, voice, and audio settings. The browser opens a direct Gemini WebSocket connection with this token; the permanent key stays on the backend. The pinned SDK uses the v1alpha constrained WebSocket endpoint. Browser transport uses native WebSocket so setup can be cancelled and send buffering can be bounded, capabilities the pinned SDK's `live.connect()` does not expose.

The microphone streams 50 ms chunks of mono signed 16-bit PCM at the browser's native audio rate, which Gemini resamples. Capture uses its own audio context so speech playback cannot change the microphone's rate. Model speech feeds a single persistent 24 kHz playback worklet with an 80 ms startup buffer. This avoids audible artifacts from restarting a browser audio source for every incoming chunk. Speaking over the persona clears queued audio when Gemini reports an interruption. Mute disables the audio tracks and flushes the input stream; End, navigation, and expiry release the microphone, both audio contexts, connection, and timers. Latest input and output transcripts appear in the practice interface. Raw recordings are not persisted by Chitchat.

Sessions can resume with their latest Gemini checkpoint after a connection reset (up to two reconnects per conversation). Resumption preserves prior context but speech in flight at the moment of a disconnect may need to be repeated. The app never silently creates a new session during recovery. Practice lasts up to 15 minutes and has no per-turn recording or turn-count limit.

Practice remains anonymous for this MVP. The backend limits token provisioning to 30 starts per minute and four concurrent requests per process. These are not per-account usage quotas. Treat the short-lived token as private; usage belongs to the configured Gemini project. The API enforces the active web origin, a small request body, and server-owned scene choices. Account quotas and persistent history are follow-up work.
