# Onboarding translations

Onboarding uses Paraglide JS with the existing selected practice language. The persisted `PracticeLanguage` identifiers stay unchanged; their locale codes live in `packages/contracts/src/languages.ts`.

## Messages and generation

- Edit `apps/web/messages/{locale}.json`. English is the base catalog.
- Keep stable message keys and preserve parameters such as `{name}` and `{count}`.
- Add locales to `apps/web/project.inlang/settings.json` and the language mapping.
- Keep compiler options in the Vite plugin and `i18n:compile` script aligned: `src/paraglide`, TypeScript declarations, and `baseLocale` strategy. Dependency and message-format plugin versions are pinned. Configuration stays outside the generated inlang metadata, which the SDK automatically ignores in Git.
- `src/paraglide/` is generated and ignored. Do not edit or commit its contents.
- Root typecheck, test, lint, and build tasks generate translations first through Turbo. Vite regenerates messages during development. No global CLI is needed.

```sh
bunx --no-install turbo run i18n:compile --filter=@chitchat/web
```

## Rendering and SSR

Use generated functions directly with an explicit locale:

```tsx
const locale = useOnboardingLocale();
return m.name_hint({}, { locale });
```

`OnboardingLocaleContext` carries the selected locale through the onboarding subtree. Its container sets `lang` and `dir`; Radix receives the same direction. The surrounding app remains English. The existing storage loading keeps SSR and the first client render identical.

This follows Paraglide's explicit-locale API. Do not call `setLocale()` from the practice-language picker: its normal behavior navigates/reloads the document. Do not mutate a global locale during SSR. If page-wide localization is added, use Paraglide's TanStack Start middleware and a server-visible locale strategy.

## Speech and generated responses

Onboarding passes locale and translated errors into the existing speech hook. Other callers retain its English defaults. The backend recommendation prompt uses the validated request language; skill IDs remain stable.

Welcome recordings are derived from `welcome_greeting` and `welcome_body`. Generate them with backend credentials, using the existing audio pipeline:

```sh
bunx --no-install turbo run generate:chit-introductions --filter=@chitchat/backend -- --welcome
```

An optional `--language=ja` limits generation to a locale; `--force` regenerates its clip and transcription. The manifest is updated only after transcript and timing validation passes. Missing recordings show localized text and keep the typing/microphone choices available. Audio transcripts and catalog wording must stay in sync; changing recorded copy requires regenerating its recording.

The initial non-English UI catalogs were machine translated and spot checked. Native-speaker editorial review remains useful before public release.

## Verification

Catalog tests check every supported language, message keys, parameters, and recorded welcome text/timing. Integration tests cover English, Japanese, Filipino, and Arabic journeys, language changes, restored drafts, and localized microphone errors. Run the root typecheck, lint, test, and build commands.
